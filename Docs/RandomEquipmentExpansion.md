## 2026-11-03 低概率晋升与高品质标记（覆盖前版限制）

原始 SourceRarity=0 仍只允许普通/魔法/稀有；=1 允许普通/魔法/稀有/史诗，当前 AffixCountWeights=50/30/15/5，史诗概率5%；=2允许史诗/传奇，用户指定传奇25%、史诗75%；=3保留传奇/独特各50%。SourceTwoLegendaryChance 为独立的[0,1]概率，不受源3高档相对权重影响，也不取决于 AffixCountWeights；非法概率拒绝生成。规则版本6。

正式配置来源为 Scripts/EquipmentImport/random_equipment_v2.json：source_two_legendary_chance=0.25。迁移脚本将其保存到五个 DA_Generation_*，运行时从物品的 GenerationProfile.SourceTwoLegendaryChance 读取。0/1低档使用 AffixCountWeights；3使用 Rarities 对应权重。高档仍4条普通随机词条，传奇威能和独特效果未实现。

FUmbraItemInstance.HasSpecialEffect()/IsUnique() 根据已保存的实例品质返回预留特殊效果身份/独特标记；不重复保存可与品质冲突的布尔值，不产生GE或战斗加成。Tooltip向WBP暴露 bHasSpecialEffect/bIsUnique，传奇显示“特殊效果待实现”，独特另显示“独特物品”。标记随原有品质的复制/记录恢复而保留；低品质重用Tooltip时清除。已有高品质实例也可显示标记，已有物品品质不重掷。
## 2026-11-03 法环原始稀有度限制随机品质

正式 V2 每件定义的 Generation.SourceRarity 从 Library 来源元数据 item.raw_params.rarity 导入。0/1 仅普通/魔法/稀有，2 仅史诗，3 仅传奇（用户称传说）/独特；-1 表示旧测试/未导入物品，沿用旧规则。非法源值或允许范围内全零权重直接拒绝生成，不降级或回退到禁止品质。限制在品质抽取前应用，不改变分类、具体类型和模板选择概率。

普通/魔法/稀有继续使用 AffixCountWeights 的 50:30:15，相对权重在允许集合内重新归一化；史诗固定4词条。原始3使用 Profile.Rarities 的 Legendary/Unique 权重，默认1:1，两档各4条普通随机词条，未增加传奇威能或独特专有效果。生成配置 Scripts/EquipmentImport/random_equipment_v2.json 的 high_rarity_weights/high_rarity_affix_count 为生产来源，rules_version 更新至5。运行时高档权重/词条数由各 DA_Generation_* 配置，低档仍由 AffixCountWeights 配置。

Scripts/EquipmentImport/apply_source_rarity.py 先核对580个来源再通过编辑器迁移 V2 定义和5个Profile，并更新生产配方版本；不保存 Library 原始资产。生成器同步生成 SourceRarity。旧实例保留已生成品质，新掉落使用新规则；不回溯改写背包或装备。详见本轮 Progress 验证记录。
# 全类型随机装备 V2 与盾牌、远程、施法器规则

2026-11-03。承接 [V1](RandomEquipmentProduction.md)。本轮目标是剩余150件也进入随机掉落，并先规划特殊装备的战斗规则；不实现完整格挡、投射物、施法或换装动画系统。

## 投放范围与当前行为

UE只读回读580份Library定义：296件武器分类装备、284件防具。V1已投放430件实际为146武器+284防具；此前报告写成153/277为汇总笔误，本轮按逐项清单纠正，不改变源分类。

| 本轮新增类型 | 件数 | 当前可用范围 |

| 刀8、双头剑4、大刺剑4、连枷4、镰刀4、拳套8、爪4、鞭5、特大武器13、火把4 | 58 | 随机掉落、拾取、穿脱、现有GAS；沿用原型主手普通攻击，不表示已经有各类专属动作/双持/攻击距离 |
| 小盾16、中盾24、大盾22 | 62 | 随机掉落、拾取、词条/需求展示；暂不可穿戴 |

所有580件均进入V2表。独立目标 `/Game/Items/GeneratedEquipment/V2` 保留V1及Library；名称、说明、分类、WeaponType、图标、模型、RequiredLevel和Requirements逐字段复制。不会根据当前角色、外形或调参覆盖已有需求。

当前装备可用状态为Definition.bEquippingEnabled，默认true兼容旧资产。92件特殊装备为false，并提供中文原因。服务器在创建GE或移出背包前拒绝穿戴，返回独立EquippingUnavailable结果；Tooltip明确提示“可拾取保留，暂不可穿戴”。物品没有伪装成近战武器的WeaponProfile，已有词条保存于实例但在背包中不生效。未来开放使用需要完成对应规则、测试及受控迁移，不应只切换布尔值。

这次所有特殊装备仍保持原有Weapon分类；盾牌的防御词条资格由独立盾牌池与WeaponTypes限制表达，不修改源分类来获得防御属性。

## 掉率设计

保留“大类 → 具体类型 → 模板”三层抽取。武器大类40%，防具60%；四个防具部位仍各占总装备15%。武器类型权重总和100，由以下设计表固定，完全不读取某类资产数量。

| 武器内部类型 | 权重 | 占全部装备 |
| --- | ---: | ---: |
| 单手剑 | 7 | 2.8% |
| 双手剑 | 6 | 2.4% |
| 匕首、矛 | 各5 | 各2% |
| 刺剑、单手斧、双手斧、单手锤、双手锤、戟、刀 | 各4 | 各1.6% |
| 双头剑、大刺剑、镰刀 | 各3 | 各1.2% |
| 连枷、拳套、爪、特大武器 | 各2 | 各0.8% |
| 鞭、火把 | 各1 | 各0.4% |
| 小盾、中盾、大盾 | 4 / 7 / 4 | 1.6% / 2.8% / 1.6% |
| 弓、弩、弩炮 | 6 / 3 / 1 | 2.4% / 1.2% / 0.4% |
| 法杖、圣印记 | 3 / 2 | 1.2% / 0.8% |

武器内部预算：近战70%、盾15%、远程10%、施法器5%；相对全部装备分别28%、6%、4%、2%。这使已能使用的近战占主要份额，尚处于规划阶段的特殊装备也保持明确产出。法杖虽然只有1件，其类型仍有固定1.2%总装备概率；中盾24件不会因数量多而占24倍概率。各类型内模板目前等权。

这些是原型初始权重，不声称已经做过长期经济平衡。无掉落机会/件数仍独立配置；当前原型每次死亡尝试生成1件，物理落点失败仍可能无实物。新增类型必须明确增加/重新分配权重；没有模板的正权重类型拒绝发布，不偷偷重抽。

## 词条与基础数值

数量权重仍50/30/15/5，1–4条对应普通至史诗。传奇威能和独特专用定义未实现，正式投放不生成传说或独特。沿用已有离散梯度，不因类型扩容或品质提高自动放大词条数值。

- 近战：通用主属性/生命、暴击率、匹配基础伤害通道的普通攻击A区增伤。火把使用现有Fire通道，10–20基础伤害；没有新增点燃/照明效果。其余新增类型的原型伤害区间和重量见JSON，不推断原游戏战斗值。
- 盾：通用 + 护甲、魔抗，不含伤害/暴击。两个防御词条复用现有Armor梯度，魔抗仍是原生评分单位。固有防御只是将来穿戴使用的预设，背包中不发放GE；没有假造“格挡率”或“格挡强度”已生效词条。
- 远程：通用 + 暴击率 + 普通攻击穿刺A区增伤。它们保存真实随机结果，但等待远程攻击实现和开放装备后才可能生效；不提供假的射速/装填/弹药效果。
- 施法器：通用 + 技能六种魔法通道A区增伤（Fire/Lightning/Cold/Radiant/Poison/Shadow，AttackSource=Skill）。沿用现有A区梯度，不写派生AD/AP，不把源proper需求值或correct补正值当作施法倍率。没有未生效的冷却/耗蓝词条。

默认值入口为 [random_equipment_v2.json](../Scripts/EquipmentImport/random_equipment_v2.json)，运行时以生成的DataAsset为准。分类、需求来自当前Library定义；基础战斗值和掉率来自配置；词条梯度来自现有MVP/M4定义。未提供静默单件覆盖机制，手改正式资产会在创建器复验时报冲突并保留。

## 盾牌规则规划（尚未实现）

1. 预留OffHand槽位，保持Weapon分类与SmallShield/MediumShield/Greatshield类型。双手武器占用双手、盾与双手武器的互斥须由装备事务统一处理；现有类型名不等于已经实现双手占用。
2. 固有护甲/魔抗、重量和主属性需求沿用装备/GAS链。格挡需要独立的守势输入、有效朝向/角度、可格挡伤害通道与资源成本；不把被动护甲直接当成格挡率。
3. 服务端在现有统一伤害执行中处理格挡阶段：伤害加成、暴击、易伤之后，抗性减伤之前，生成一次最终IncomingDamage。具体比例、消耗及破防阈值单独调参；不在UI或盾Actor再算一遍伤害。
4. 上线测试覆盖背后/范围外攻击、魔法格挡规则、资源不足/破防、切换装备、双手冲突、主属性不足惩罚与网络状态。小/中/大盾的差异由格挡配置表达，不由导入模型数量表达。

## 远程规则规划（尚未实现）

1. 主手装备，弓/弩/弩炮各自配置攻击Ability、射速或装填阶段、射程、弹道和碰撞；远程输入不得回落到近战挥砍。双手占用规则与装备事务一起实现。
2. 发射由服务器确认；在一次发射中准备并保存攻击Spec/基础伤害采样，命中沿用现有TypedDamage链，避免客户端重复随机或同一弹体多次结算。源攻击快照与命中时目标防御的时点需在实现中固定并测试。
3. 首个远程原型可使用无消耗测试弹，不因此扩展完整弹药库存系统。箭/弩箭资源不自动转成随机武器，不用模型源分类替代攻击能力。
4. 测试覆盖遮挡/射程/空射、移动目标、装填取消、弹体销毁、重复命中、卸装后在途弹体、延迟及丢包。稳定后再开放本轮已保存的远程装备实例。

## 施法器规则规划（尚未实现）

1. 首版主手专用：法杖/圣印记作为技能施放媒介，绑定明确的技能资格或能力标签，不自动当成近战棍。未来副手媒介须先扩展主副手伤害来源选择。
2. 施法基础与智力/信仰补正使用项目配置和曲线，结果进入已有派生属性/TypedDamage链；不直接映射源CSV补正，不由UI计算法术威力。具体法术的系数仍由对应Ability配置。
3. 消耗、施放时间、打断、冷却和类型过滤在Ability/GAS层实现。装备上的SpellA只影响满足条件的技能魔法伤害，不提高物理普通攻击或擅自改派生AD/AP。
4. 测试覆盖缺少媒介、属性需求惩罚、资源不足、施放中切换、打断后扣费、技能标签过滤及网络结果。首次仅验证一项代表法术，避免扩展成完整技能树。

## 生产与验证入口

`PrepareRandomEquipment.ps1 -Apply -Activate` 默认使用V2；`-Config <V1 JSON绝对路径>`仍可显式审计/恢复旧入口，V1资源不覆盖。生产脚本要求本批完整580件，缺项或异常时不把部分成功报告为完成。先构建UmbraEditor，再通过匹配UE执行生产、资产测试和PIE，最后接入敌人。

生产身份前缀RandomV2与旧RandomV1分开，旧实例保留原定义和随机结果，不自动迁移；当前项目尚未实现长期存档。创建器比对字段及配方，重复运行零写入；来源/用途/可装备状态写入报告。

验证入口：`Umbra.Items.Generation.ProductionLoot`、`ProductionAssets`、`StagedEquipment`，以及现有Generation/Inventory/Equipment/UI.Items回归。PIE覆盖各类型真实死亡掉落、拾取，近战/防具穿脱，特殊装备服务端拒绝穿戴且物品不丢失。实际结果见 [Progress](Progress.md)，未完成的格挡、远程和施法行为不能用掉落测试冒充验收。
