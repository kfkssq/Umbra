## 动画、逻辑、表现三层契约

拟新增名称仅表达设计，不代表已有 API；实现时按最少必要类型落地。

| 层 | 配置内容 | 责任 |
| --- | --- | --- |
| SkillDefinition | 稳定 SkillId、Ability 类、费用/冷却、伤害配置、投射物基础参数、动作/表现引用 | 不可变基础数据；UI 观察运行时结果 |
| SkillAnimationProfile | 骨架、Montage/Section、播放速率、释放时间、恢复时间、Socket、移动/根运动策略 | 定义动作与逻辑时刻的映射；不直接生成伤害或绑定具体 VFX |
| SkillPresentationProfile | CastStart/Release/Flight/Impact/Bounce/Expire/Cancel 的 Niagara、声音、挂点和偏移 | 纯表现；丢失或关闭表现不改变命中结果 |
| 运行时施放快照 | CastId、解析后的参数、动作时序、强化来源与版本 | 服务器冻结本次施放规则；不修改共享 DataAsset |
| Ability / Projectile | 激活、扣费/冷却、中断、生成、碰撞、去重、伤害请求、寿命 | C++ 维护可复用规则，蓝图配置资源与调参 |

建议数据流：输入 → GAS 激活/提交 → 服务器生成施放快照 → 动作阶段调度 → 生成投射物 → 服务器碰撞 → UmbraDamage::Apply → GAS 结算；阶段事件同时交给表现层。

第一版继续采用服务器计时，动作配置中的 authored seconds 除以播放速率得到真实时间，施放中不动态改速。Notify 用于编辑器对齐/纯表现参考，不能与计时器各自生成一发弹。Release 按 CastId + 阶段序号只执行一次；缺失 Montage/非法 Socket 在扣费前预检。换动作必须校验释放点仍位于有效段内，不承诺任意动作自动适配。

表现只消费事件和投射物状态，不参与碰撞。瞬时事件携带 CastId、ProjectileId、事件序号、位置/法线及表现引用；持续尾迹/循环音绑定投射物生命周期，以复制状态重建和销毁。专用服务器不播放。保留现有服务器发起模式，首版不新增客户端预测系统；验证客户端不重复播放、不重复提交伤害。

音频显式分为起手、释放、飞行循环、命中、反弹、消散/取消。复用已有音频库的类别音量、衰减和并发约定，补充循环实例句柄的停止/淡出能力。技能命中音与现有 GAS 通用受伤音明确分工，避免同一声音播放两次。多弹时起手/释放按施放一次，飞行与撞击按实例且受并发限制；取消、死亡、销毁和切图清理循环音与附着特效。

## 首个自定义技能及变异规则

“幽焰裂矢”建议初值（均待实测）：起手释放 0.35 秒，冷却 2 秒，资源 10，单发速度 1400 cm/s，碰撞半径 12 cm，寿命 2 秒，总路径上限 2800 cm。通过现有 Typed Damage 的显式通道配置一种伤害，基础值/AD/AP 系数在 Definition 配置，减伤、暴击和 A/X 区仍由现有 GAS 链处理。

“反弹”拆为两种独立能力：撞墙按法线反射方向，以及命中敌人后选择新敌人跳弹；避免用同一个计数混淆两种行为。

| 参数 | 原型默认/示例 | 规则与边界 |
| --- | --- | --- |
| ProjectileCount / Spread | 1 → 3，扇面总角 20° | 对称发射，偶数不强制中心弹；每次施放只扣一次费用/冷却；原型数量上限 8 |
| PierceCount | 0 → 2 | 指额外穿过的敌人数；值 2 最多命中 3 个不同敌人，不穿墙 |
| WallBounceCount | 0 → 1 | 墙面反射最多一次；离开接触面后再允许新碰撞，设置最小位移/接触去重 |
| ChainCount / SearchRadius | 0 → 2 / 500 cm | 命中后在可攻击、未命中、无遮挡目标中选最近者；距离相同用服务器稳定标识排序，无目标则销毁 |
| DamageRetention | 跳弹每次 0.8 | 进入下一跳才乘一次；穿透默认不衰减，墙反射默认不衰减，各自独立配置 |
| MaxLifetime / MaxTravelDistance | 2 s / 2800 cm | 从生成起累计，反射/跳弹不重置；到上限立即终止；额外总碰撞次数保护 |

组合优先级：敌人有效首次命中 → 提交一次伤害 → 有穿透余量则扣一次并继续直行 → 否则尝试敌间跳弹 → 否则销毁。世界阻挡只处理墙反射，否则销毁，不触发敌间跳弹。死亡/无效目标不消耗敌人命中预算。友方过滤复用项目攻击资格规则，不能只按 Actor 类名判断。

去重键使用 ProjectileId + Target；同一弹终生不能再次伤害同一目标，多个碰撞组件只算一次。多发弹允许分别命中同一敌人，因此数量强化默认增加单体总伤害；若后续要限制霰弹叠伤，增加明确策略而非隐式除以弹数。三发、Pierce=2、Chain=2 时每发最多命中 5 个不同敌人，整次最多 15 次伤害提交；墙反射不增加此上限。使用扫掠碰撞验证高速弹不穿过薄墙/敌人。

释放前中断：不生成弹，沿用当前提交后不退款规则；释放后中断：取消角色后续表现，已发射弹继续到正常终止，施法者死亡同理；施法者/ASC 已销毁则停止新伤害并清理弹体。异常/切图清理不生成新的伤害事件。

## 强化来源与覆盖顺序

分清“数值强化”（伤害、速度、数量、冷却）与“行为变异”（穿透、反射、跳弹）；每个修改器有稳定 ID、来源 ID、层数上限、支持的技能标签/参数。首版仅由开发配置授予/移除，不新增技能树或装备词缀接入。

基础 Definition → 等级调参曲线（首版可固定 Level 1）→ 已授予修改器汇总 → 合法性与上限校验 → 本次施放快照。数值统一为 (Base + ΣAdd) × ΠMultiplier；数量/次数只接受整数加法。互斥行为覆盖按显式优先级选择，同优先级冲突报错，不以数组顺序决定。表现覆盖只替换 Profile，不改玩法参数。

源导入配方只生产基础 Definition，不直接覆盖运行时强化。非法 NaN/负寿命/无效组合拒绝激活；合法但超出设计上限的数量钳制并在调试报告记录。行为上限集中在开发规则配置，实例不能自行提高。撤销修改器从基础重算，不能在旧结果上减回；同一来源重复授予不能意外叠层。

施放快照冻结数量、弹道、费用、冷却和技能伤害配置；命中时攻击者/目标的 GAS 属性、抗性和条件效果沿用现有结算时机。不会因为引入快照就冻结整套 GAS。UI 读取同一个已解析参数视图及真实冷却 GE，不重算强化公式。
