# 18件跨类型装备批量测试（2026-11-01）

结论：当前默认规则能完成部分普通装备的自动导入，但不能称为覆盖大多数装备。本次18件中7件完成模型/材质/icon导入（38.9%），11件在转换阶段被明确规则拒绝。样本刻意覆盖边界，不是随机抽样，不能用38.9%推算整个资源库成功率。

所有入选记录均先通过模型和icon存在、精确关联门槛；没有复用此前匕首/旅行手套作为这批的成功样品。源数据版本仍为未确认。

- Previews：每件两个角度的真实材质光照图及BaseColor缓冲，共28张。逐件查看了BaseColor预览；模型轮廓与贴图存在，未看到明显缺块/默认棋盘格。臂甲仍保持参考姿势下两个分离部位，未强行拼接。金属光照图偏暗，BaseColor缓冲也不是原游戏色调映射截图，因此**不据此宣称原版外观还原通过**。

- 33项Python回归通过；实际UE材质编译通过。首次创建曾出现1条法线纹理尚无miplevels的警告，后续新进程回读/预览继续检查，不能以初次告警直接认定源贴图损坏。

## 测试工具及失败隔离

[选择清单](../Scripts/EquipmentImport/batch_test_selection.json) 固定源身份，防止重复/派生记录充数。[测试入口](../Scripts/EquipmentImport/batch_equipment_test.py) 先检查资源门槛，逐包转换并保留失败，让成功包继续进入UE。转换失败的包不创建草稿；总体有失败时返回非零，成功资产保留。

编辑器桥接补充逐行失败隔离，以及测试计划显式开启的unmapped asset-only分支。普通物品导入入口仍要求有分类映射；测试脚本不修改分类枚举。转换层11件失败和7件继续导入已实际验证，未注入模拟UE导入崩溃。

[预览脚本](../Scripts/EquipmentImport/batch_equipment_preview.py) 使用独立空白世界，顺序加载并销毁预览Actor，不保存地图。通过UMBRA_BATCH_REPORT指定报告，UMBRA_PREVIEW_MODE=basecolor用于贴图诊断。

## 下一轮应修什么

1. **区分主法线与细节法线。** 战斧引用AAT100_Fabric_03_n（10倍UV），戟引用AAT100_Metal_02_n（5倍），辉石杖引用AAT100_Bone_01_n（3×0.5）。这是detail层，不应直接当作主_n文件冲突；应解析层级、保留主法线，并把未实现的detail混合单独报告。当前测试没有绕过检查。
2. **增加wood、Belt_Leather和无后缀模板的有证据规则。** 共4件，不能仅把未知模板统统当成metal。
3. **审核Alpha用途。** 共3件；区分裁切、材质mask、无用Alpha后再自动Masked/Ignore，不能统一忽略。
4. **处理贴图别名。** 皮革长裤需要检查真实TPF纹理名和FLVER引用；不按相似数字猜选。
5. **之后再提高还原度。** 验证金属/粗糙度通道、混合材质和环境光照。提高导入成功率与还原原材质是两项不同验收。

本轮没有为了提高成功率调整默认材质规则或覆盖失败样品。
